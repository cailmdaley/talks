Part A: Build from scratch — Union2.1 Type Ia Supernovae (15–20 min)

Create a fresh folder and start your agent (claude --model sonnet, opencode, or codex):

mkdir sn-cosmology && cd sn-cosmology
claude --model sonnet   # or: opencode / codex

Step A1 · Specify and materialize flat ΛCDM

Start a new Lightcone analysis fitting a flat LCDM model to the Union2.1 supernova compilation to recover Omega_Lambda, holding H0 = 70 km/s/Mpc as given in the file's header.

Download the data into data/:
  https://supernova.lbl.gov/Union/figures/SCPUnion2.1_mu_vs_z.txt

Use numpy, scipy (scipy.integrate.quad for luminosity distance), and matplotlib. Produce two outputs in astra.yaml:
1. best_fit (metric, format: json) — Omega_Lambda, 1-sigma uncertainty from delta-chi2 = 1, chi2, dof
2. hubble_diagram (figure, format: png) — distance modulus vs redshift with best-fit LCDM and Einstein-de Sitter curves, plus residuals panel

Don't add any decisions yet. Initialize with `lc init`, launch a local cluster with `lc compute launch --wait`, materialize both outputs with `lc materialize local`, and report the fitted Omega_Lambda.

Expected result: ΩΛ = 0.722 ± 0.013 (χ2/dof = 562.2 / 579 = 0.97).

Step A2 · Verify the published constraint against the PDF

The paper that published this catalogue is Suzuki et al. 2012, arXiv:1105.3470.

Cache the paper with `uvx --from astra-tools==0.2.18 astra paper add 10.48550/arXiv.1105.3470`, locate their SNe-only flat-LCDM Omega_Lambda constraint (including systematics), record it in astra.yaml as a prior_insight with the exact quote and page number, and run `uvx --from astra-tools==0.2.18 astra validate astra.yaml --verify-evidence`.

Then compare our constraint to theirs.

Suzuki et al. (2012), page 17, report ΩΛ = 0.705+0.040−0.043 including systematics — central value agrees, error bar is 3× too tight.

Step A3 · Diagnose systematics and record an ASTRA decision

Let's figure out why our error bars are 3x tighter than Suzuki et al. (2012). Download both Union2.1 covariance matrices into data/:
  https://supernova.lbl.gov/Union/figures/SCPUnion2.1_covmat_nosys.txt
  https://supernova.lbl.gov/Union/figures/SCPUnion2.1_covmat_sys.txt

Check which covariance matrix's diagonal matches the data table's error column. Then add a `covariance` decision to astra.yaml with options `stat_only` and `full` (default `full`), define two universes (`universes/baseline.yaml` and `universes/stat_only.yaml`, nesting options under `decisions:`), materialize both universes with `lc materialize local`, and print a comparison table.
AnalysisΩΛχ2 / dof
Statistical only (stat_only, fixed M)0.722 ± 0.013562.2 / 579 (0.97)
Statistical + systematic (full, fixed M)0.714 ± 0.030545.2 / 579 (0.94)
Stat + sys, marginalized over ΔM (bonus decision)0.705 ± 0.041545.1 / 578 (0.94)
Suzuki et al. (2012), page 170.705 (+0.040, −0.043)—

The table error column matches √diag(Cnosys) to 6.7×10−12. Including the systematic covariance doubles the error bar (0.013 → 0.030); adding a second ASTRA decision that marginalizes over the constant distance-modulus zero-point ΔM reproduces Suzuki et al.'s published constraint (0.705+0.040−0.043) to three significant figures.

Part B: Explore & modify a published cosmology paper — UNIONS-3500 B-modes (15–20 min)

Now step up to a real published analysis: UNIONS-3500 Weak Lensing: II. B-mode validation for cosmic shear (Daley et al. 2026, accepted by A&A). The laptop branch ships the measured harmonic-space Cℓ and real-space ξ± bandpowers and covariances for every catalog and PSF-leakage variant so you can toggle decisions and remake figures on your laptop.

Step B1 · Clone the full laptop branch and open the viewer

Run this in a parent folder (full clone without --depth 1 so lc can verify commit provenance):

git clone -b laptop --single-branch https://github.com/cailmdaley/unions-bmodes-mystra paper-ii
cd paper-ii
lc init
lc compute launch --wait

# Option 1: Lightcone Studio (interactive click-to-run viewer)
npx github:LightconeResearch/ui-prototype#click-decision --run

# Option 2: Lightcone Lab in JupyterLab (public on PyPI)
uv tool install jupyterlab --with "jupyterlab-lightcone[full]"
jupyter-lab

You can also browse the published static report directly at cailmdaley.github.io/unions-bmodes-mystra/report/.

Step B2 · Click a decision live in Studio (~13 s)

  1. Walk through the paper's Decisions, Lineage graph, Provenance, and Bibliography tabs.
  2. Open fig_cl_fiducial (the 32-bin harmonic-space B-mode figure) and click fiducial_catalog → initial (or masked, relaxed_flags, leakage_correction → uncorrected).
  3. Watch the pending state in the Queue tab while lc materialize runs (~13 s); once it lands, toggle between baseline and the new universe instantaneously.

Step B3 · Prompt your coding agent inside paper-ii/

Open your agent inside paper-ii/ (its CLAUDE.md documents every locally runnable decision and how to rematerialize) and try one or both prompts:

Turn off PSF leakage correction (leakage_correction=uncorrected) and remake the pure E/B data vector figure in a new universe. Compare the B-mode PTEs to baseline and summarize what changed in 2–3 sentences.
Edit the harmonic-space C_ell data vector plotting script to highlight the fiducial scale cut with a subtle shaded band, commit the change, remove the old figure + manifest, and rematerialize baseline/significance.cl_data_vector_figure.

Try asking for something that cannot run on a laptop (e.g. "switch to Blind B" or "switch to adaptive quadrature") — watch the agent read the project constraints and decline cleanly in seconds rather than fabricating a workaround.

Clean up when done

lc compute down local
