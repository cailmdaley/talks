Simulations are a verifiable environment for agents

  • mock inputs are a known quantity, so agents can check their own work
  • designing analyses in a way that builds in verification pressure
  • condition on observational properties as much as possible
  • Spoken, on the last line — in UNIONS the GLASS mocks start from the real shape catalog: positions, magnitudes, ellipticities and all of the PSF information are kept, the shapes are randomized and then sheared by a GLASS field. PSF leakage can then be injected with the actual PSF model. That playground is what the agents work in.
  • Spoken, the bitter lesson — Richard Sutton's observation that methods which scale with search and learning end up beating hand-built expertise. You can build the experiment by hand, or build a program that learns from data by running experiments on simulations. We have historically designed estimators; the work may become mostly designing simulations that enable search and learning, and not at the level of parameter constraints but at the level of scaling the problem.
  • The checking — against a simulation whose answer is known: input spectra recovered by the bandpower code, input cosmology recovered by the chains, an injected systematic recovered by its fit.
  • Higher-level requirements — what the analysis must recover, to what accuracy and under which systematics, rather than how each step is coded.
  • In this talk — in Cail's own work, the UNIONS v2 catalog production and the Euclid × CMB lensing data vectors, mocks and chains are built and run by coding agents, inside reproducible pipelines that record what each result came from.
